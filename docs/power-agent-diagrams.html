📋 节点说明

agent — 调用 LLM（绑定 17 个 @tool），是整个状态机的核心驱动节点
inject_session — 工具执行前给每个 tool_call.args 注入 session_id，实现多会话隔离
tools — 批量执行 LLM 决定调用的工具，由 GraphService._tools_node 实现（注册表优先，回退 ALL_TOOLS）
skill_check — 统一后置检查节点（LLM 出 tool_calls / 直接回答 两种路径都会走到这里），调用 SkillRouter.match_after_llm 做意图 + 电网状态双重判定，命中则写 matched_skill 并把 skill_route 置为 end
菱形判断 — should_continue 决定走 tools 还是直接 skill_check；route_after_skill 读取 state.skill_route 决定回到 agent 还是结束
前置 Skill 通道（不在图内） — GraphService.chat_stream 里在进入编译图前先调 SkillRouter.match()，复合意图（含断线/切负荷/投运等 pre_action_triggers 词）不抢跑，纯意图命中则直接接管
